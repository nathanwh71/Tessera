# Phase Oct: the user stories, in build order

Thirty <span style="color:grey">user</span> <span style="color:grey">stories</span>, in the <span style="color:grey">order</span> you <span style="color:grey">build</span> them. <span style="color:grey">Each</span> <span style="color:grey">builds</span> <span style="color:grey">only</span> on <span style="color:grey">stories</span> <span style="color:grey">above</span> it, so you can <span style="color:grey">build</span> and <span style="color:grey">ship</span> them <span style="color:grey">one</span> at a <span style="color:grey">time</span> from the <span style="color:grey">top</span>. They <span style="color:grey">build</span> <span style="color:grey">two</span> <span style="color:grey">things</span>: an HTTP API that <span style="color:grey">serves</span> a ***tile*** of a ***layer***, and a <span style="color:grey">map</span> that <span style="color:grey">shows</span> those <span style="color:grey">tiles</span>. <span style="color:grey">Office</span> <span style="color:grey">machines</span> <span style="color:grey">call</span> the API on <span style="color:grey">port</span> 80, in <span style="color:grey">plain</span> HTTP, and <span style="color:grey">ask</span> for <span style="color:grey">each</span> <span style="color:grey">tile</span> by <span style="color:grey">layer</span> <span style="color:grey">name</span>; no <span style="color:grey">client</span>, the <span style="color:grey">map</span> <span style="color:grey">included</span>, <span style="color:grey">loads</span> a <span style="color:grey">list</span> of <span style="color:grey">layers</span>.

The <span style="color:grey">stories</span> <span style="color:grey">say</span> what Tessera must do and how to <span style="color:grey">prove</span> it. Where a <span style="color:grey">part</span> of the <span style="color:grey">build</span> does the <span style="color:grey">work</span>, they <span style="color:grey">name</span> it: Nginx <span style="color:grey">stands</span> in <span style="color:grey">front</span> of the <span style="color:grey">service</span> (ADR 0008), DbUp <span style="color:grey">loads</span> the <span style="color:grey">places</span> (ADR 0009), and `tessera.json` <span style="color:grey">holds</span> the <span style="color:grey">settings</span> (ADR 0003). <span style="color:grey">Standards</span> that <span style="color:grey">fix</span> the <span style="color:grey">data</span> or the interface are <span style="color:grey">named</span>: HTTP, RFC 9457's <span style="color:grey">problem</span> <span style="color:grey">details</span>, GeoJSON, WGS 84 and ***Web Mercator***; so is Material 3, the <span style="color:grey">design</span> <span style="color:grey">system</span> of the <span style="color:grey">map</span>, in the NTessera <span style="color:grey">Project</span>'s `claude/design/map/`. <span style="color:grey">One</span> <span style="color:grey">story</span> <span style="color:grey">names</span> its <span style="color:grey">platform</span>, <span style="color:grey">because</span> the <span style="color:grey">office</span>'s <span style="color:grey">machine</span> <span style="color:grey">fixes</span> it: US-35 <span style="color:grey">opens</span> <span style="color:grey">port</span> 80 on Ubuntu 24.04 <span style="color:grey">inside</span> WSL2 on <span style="color:grey">Windows</span> 11. <span style="color:grey">Each</span> <span style="color:grey">number</span>'s <span style="color:grey">letters</span> <span style="color:grey">mark</span> its <span style="color:grey">kind</span>: <span style="color:grey">US</span> for the <span style="color:grey">service</span>, S for <span style="color:grey">security</span>, N for <span style="color:grey">tiles</span> that <span style="color:grey">cost</span> <span style="color:grey">less</span> and a <span style="color:grey">service</span> that <span style="color:grey">stays</span> steady, and UI for the <span style="color:grey">map</span>.

The <span style="color:grey">stories</span> <span style="color:grey">name</span> **the area**, the <span style="color:grey">place</span> the <span style="color:grey">tiles</span> <span style="color:grey">cover</span>, in <span style="color:grey">place</span> of Macau. Its <span style="color:grey">name</span>, its <span style="color:grey">box</span> and its <span style="color:grey">home</span> <span style="color:grey">view</span> are <span style="color:grey">settings</span>: the <span style="color:grey">office</span> <span style="color:grey">sets</span> them to Macau, and every <span style="color:grey">figure</span> the <span style="color:grey">stories</span> <span style="color:grey">give</span> for the <span style="color:grey">area</span> is Macau's.

## INVEST in plain words

Every <span style="color:grey">story</span> <span style="color:grey">meets</span> <span style="color:grey">six</span> <span style="color:grey">tests</span>, which <span style="color:grey">together</span> <span style="color:grey">spell</span> INVEST.

- **Independent.** The <span style="color:grey">story</span> <span style="color:grey">needs</span> <span style="color:grey">only</span> <span style="color:grey">stories</span> <span style="color:grey">above</span> it, and <span style="color:grey">none</span> <span style="color:grey">below</span>. <span style="color:grey">Once</span> those are <span style="color:grey">built</span>, you can <span style="color:grey">build</span> and <span style="color:grey">ship</span> it on its <span style="color:grey">own</span>; 'Builds on' <span style="color:grey">names</span> them.
- **Negotiable.** The <span style="color:grey">story</span> <span style="color:grey">fixes</span> the <span style="color:grey">need</span>, not the <span style="color:grey">design</span>. 'Open to talk' <span style="color:grey">lists</span> what may <span style="color:grey">still</span> <span style="color:grey">change</span>.
- **Valuable.** Its 'so that' <span style="color:grey">names</span> who <span style="color:grey">gains</span> and what. A <span style="color:grey">story</span> for the <span style="color:grey">maintainer</span> is an *enabler*: it <span style="color:grey">gives</span> no <span style="color:grey">client</span> <span style="color:grey">anything</span> <span style="color:grey">new</span>, but it unblocks the <span style="color:grey">stories</span> that do.
- **Estimable.** It is <span style="color:grey">clear</span> <span style="color:grey">enough</span> to <span style="color:grey">size</span>, in <span style="color:grey">points</span>.
- **Small.** No <span style="color:grey">story</span> exceeds 3 <span style="color:grey">points</span>.
- **Testable.** Every <span style="color:grey">criterion</span> can <span style="color:grey">pass</span> or <span style="color:grey">fail</span>, and 'Tests to write first' <span style="color:grey">says</span> how to <span style="color:grey">prove</span> the <span style="color:grey">first</span> <span style="color:grey">ones</span>.

The <span style="color:grey">table</span> at the <span style="color:grey">end</span> <span style="color:grey">checks</span> <span style="color:grey">each</span> <span style="color:grey">story</span> <span style="color:grey">against</span> all <span style="color:grey">six</span>.

### Step 1 · US-00 Set up the walking skeleton

| | |
|---|---|
| Size | 1 <span style="color:grey">point</span> |
| Builds on | <span style="color:grey">nothing</span> |

**In plain words.** A <span style="color:grey">builder</span> pegs out the <span style="color:grey">site</span> <span style="color:grey">before</span> <span style="color:grey">laying</span> a brick. This <span style="color:grey">story</span> <span style="color:grey">lays</span> out the codebase and <span style="color:grey">lets</span> <span style="color:grey">one</span> <span style="color:grey">command</span> <span style="color:grey">build</span> the <span style="color:grey">service</span>, and another <span style="color:grey">run</span> it. The **walking skeleton** is the thinnest <span style="color:grey">service</span> that <span style="color:grey">works</span> <span style="color:grey">end</span> to <span style="color:grey">end</span>: an <span style="color:grey">answer</span> from the <span style="color:grey">service</span>, on your <span style="color:grey">screen</span>.

> **Story.** **As** the <span style="color:grey">maintainer</span>, **I want** a codebase that <span style="color:grey">builds</span> and <span style="color:grey">runs</span> from <span style="color:grey">one</span> <span style="color:grey">command</span>, **so that** every <span style="color:grey">later</span> <span style="color:grey">story</span> <span style="color:grey">starts</span> from <span style="color:grey">working</span> <span style="color:grey">ground</span>.

**Acceptance criteria**

1. **Given** a <span style="color:grey">fresh</span> <span style="color:grey">copy</span> of the repository, **when** I <span style="color:grey">run</span> the <span style="color:grey">build</span> <span style="color:grey">command</span>, **then** the <span style="color:grey">service</span> <span style="color:grey">builds</span>.
2. **Given** the <span style="color:grey">build</span>, **when** I <span style="color:grey">run</span> the <span style="color:grey">run</span> <span style="color:grey">command</span>, **then** the <span style="color:grey">service</span> <span style="color:grey">starts</span> and <span style="color:grey">answers</span> an HTTP <span style="color:grey">request</span> on its <span style="color:grey">port</span>.

**Critical to success**

- **Build and run from one command, from the first day.** <span style="color:grey">Each</span> <span style="color:grey">later</span> <span style="color:grey">story</span> then <span style="color:grey">adds</span> to a codebase that <span style="color:grey">already</span> <span style="color:grey">runs</span>.

4. **A replaced table waits for its grant.** A <span style="color:grey">new</span> <span style="color:grey">script</span> that <span style="color:grey">replaces</span> a <span style="color:grey">granted</span> <span style="color:grey">table</span> <span style="color:grey">leaves</span> it unpublished until the <span style="color:grey">next</span> <span style="color:grey">grant</span>.
5. **The pipeline's own rules.** ***Unit tests*** in `tests/Tessera.Etl.Tests`: INSERT <span style="color:grey">statements</span>, a <span style="color:grey">numbered</span> <span style="color:grey">key</span>, EPSG:4326, GDAL's <span style="color:grey">own</span> <span style="color:grey">transaction</span> <span style="color:grey">taken</span> out, and a <span style="color:grey">misspelt</span> <span style="color:grey">pipeline</span> <span style="color:grey">file</span> <span style="color:grey">refused</span>.

**Open to talk**

- Which <span style="color:grey">properties</span> <span style="color:grey">each</span> <span style="color:grey">place</span> <span style="color:grey">carries</span>. The <span style="color:grey">tiles</span> <span style="color:grey">carry</span> them all (US-07), `fid` <span style="color:grey">among</span> them. <span style="color:grey">Places</span> <span style="color:grey">carry</span> no <span style="color:grey">rank</span>.

**Critical to success**

- **A grant is a publication.** The <span style="color:grey">seed</span> <span style="color:grey">creates</span> the <span style="color:grey">tables</span>; the <span style="color:grey">data</span> <span style="color:grey">publisher</span> <span style="color:grey">alone</span> <span style="color:grey">publishes</span> them.
- **A script is the record.** A <span style="color:grey">committed</span> <span style="color:grey">script</span>'s SQL <span style="color:grey">never</span> <span style="color:grey">changes</span>; <span style="color:grey">new</span> <span style="color:grey">data</span> <span style="color:grey">goes</span> in a <span style="color:grey">new</span> <span style="color:grey">script</span>, so the journal and the repository agree.
- **The tile format converts, not the table.** A vector <span style="color:grey">tile</span> can <span style="color:grey">hold</span> <span style="color:grey">positions</span> <span style="color:grey">only</span> <span style="color:grey">inside</span> its <span style="color:grey">Web</span> Mercator <span style="color:grey">square</span>, so the <span style="color:grey">conversion</span> <span style="color:grey">belongs</span> to the <span style="color:grey">tile</span> <span style="color:grey">format</span> (US-07). <span style="color:grey">Each</span> <span style="color:grey">tile</span> <span style="color:grey">query</span> <span style="color:grey">finds</span> its <span style="color:grey">places</span> by the <span style="color:grey">tile</span>'s <span style="color:grey">box</span>, <span style="color:grey">converted</span> to <span style="color:grey">degrees</span>, so the spatial index <span style="color:grey">applies</span>.
- **The schema is the group.** A <span style="color:grey">layer</span>'s id, such as `food.cafes`, <span style="color:grey">names</span> its <span style="color:grey">group</span>, so a <span style="color:grey">client</span> <span style="color:grey">knows</span> a <span style="color:grey">layer</span>'s <span style="color:grey">group</span> from its <span style="color:grey">name</span> <span style="color:grey">alone</span>.
- **Typed, indexed, analysed.** An untyped <span style="color:grey">column</span> is not <span style="color:grey">published</span> (US-03), and <span style="color:grey">without</span> an index and <span style="color:grey">fresh</span> <span style="color:grey">statistics</span> every <span style="color:grey">tile</span> <span style="color:grey">reads</span> the <span style="color:grey">whole</span> <span style="color:grey">table</span>.

### Step 5 · US-07 Serve a tile

| | |
|---|---|
| Size | 2 <span style="color:grey">points</span> |
| Builds on | US-24: <span style="color:grey">places</span> to <span style="color:grey">put</span> in the <span style="color:grey">tiles</span> |

**In plain words.** This is the <span style="color:grey">heart</span> of the <span style="color:grey">product</span>. <span style="color:grey">Asked</span> for <span style="color:grey">tile</span> z/x/y of a <span style="color:grey">layer</span>, the <span style="color:grey">service</span> <span style="color:grey">returns</span> a <span style="color:grey">small</span> <span style="color:grey">file</span> of <span style="color:grey">map</span> <span style="color:grey">shapes</span> that the <span style="color:grey">database</span> <span style="color:grey">builds</span> in <span style="color:grey">one</span> <span style="color:grey">query</span>. <span style="color:grey">Whenever</span> it <span style="color:grey">cannot</span> <span style="color:grey">serve</span>, it <span style="color:grey">answers</span> with a **problem document**: a <span style="color:grey">small</span> JSON <span style="color:grey">note</span> in the <span style="color:grey">shape</span> that RFC 9457 <span style="color:grey">sets</span>, so every <span style="color:grey">client</span> <span style="color:grey">reads</span> every <span style="color:grey">error</span> the <span style="color:grey">same</span> <span style="color:grey">way</span>.

> **Story.** **As** a <span style="color:grey">map</span> developer, **I want** a <span style="color:grey">tile</span> by <span style="color:grey">layer</span> and coordinates, **so that** my <span style="color:grey">map</span> <span style="color:grey">shows</span> the <span style="color:grey">layer</span>'s <span style="color:grey">features</span>.

**Acceptance criteria**

1. **Given** a <span style="color:grey">published</span> <span style="color:grey">layer</span>, **when** I <span style="color:grey">request</span> `/{layer}/{z}/{x}/{y}.pbf`, **then** I <span style="color:grey">receive</span> 200 ('OK') with the <span style="color:grey">content</span> <span style="color:grey">type</span> `application/vnd.mapbox-vector-tile`.
2. **Given** the <span style="color:grey">same</span> <span style="color:grey">request</span> <span style="color:grey">ending</span> `.mvt`, **then** the <span style="color:grey">body</span> is <span style="color:grey">identical</span>.
3. **Given** a <span style="color:grey">layer</span> <span style="color:grey">stored</span> in WGS 84 (US-24), **when** I decode its <span style="color:grey">tiles</span>, **then** its <span style="color:grey">features</span> <span style="color:grey">sit</span> at the <span style="color:grey">right</span> <span style="color:grey">positions</span> in the <span style="color:grey">tile</span>'s <span style="color:grey">grid</span>.
4. **Given** an <span style="color:grey">unknown</span> <span style="color:grey">layer</span>, **when** I <span style="color:grey">request</span> a <span style="color:grey">tile</span>, **then** I <span style="color:grey">receive</span> 404.
5. **Given** <span style="color:grey">any</span> <span style="color:grey">error</span> <span style="color:grey">answer</span> from the HTTP API, such as the 404 <span style="color:grey">above</span> and the 400 of S-06, **then** its <span style="color:grey">body</span> is a <span style="color:grey">problem</span> <span style="color:grey">document</span> as RFC 9457 <span style="color:grey">defines</span> it: the <span style="color:grey">content</span> <span style="color:grey">type</span> `application/problem+json`, with `type`, `title` and `status`, and `detail` where a <span style="color:grey">sentence</span> <span style="color:grey">helps</span>. `status` <span style="color:grey">matches</span> the HTTP <span style="color:grey">status</span> <span style="color:grey">code</span>, and with `type` as `about:blank`, `title` is the <span style="color:grey">status</span>'s <span style="color:grey">own</span> <span style="color:grey">phrase</span>, such as 'Not Found'.

**Tests to write first**

1. **An unknown layer is not found.** The <span style="color:grey">request</span> is <span style="color:grey">refused</span> <span style="color:grey">before</span> <span style="color:grey">any</span> <span style="color:grey">query</span> <span style="color:grey">runs</span>.
2. **Through the real database.** A <span style="color:grey">tile</span> over the <span style="color:grey">sample</span> <span style="color:grey">places</span> <span style="color:grey">carries</span> their <span style="color:grey">features</span> and <span style="color:grey">properties</span>.
3. **Every error is a problem document.** For an <span style="color:grey">unknown</span> <span style="color:grey">layer</span>, the <span style="color:grey">content</span> <span style="color:grey">type</span> is `application/problem+json`, `status` <span style="color:grey">equals</span> the <span style="color:grey">status</span> <span style="color:grey">code</span>, and `title` <span style="color:grey">reads</span> 'Not Found'.

**Open to talk**

- <span style="color:grey">Whether</span> to <span style="color:grey">keep</span> the `.mvt` <span style="color:grey">ending</span>.
- The <span style="color:grey">tile</span>'s <span style="color:grey">cap</span> on <span style="color:grey">features</span> and the buffer of <span style="color:grey">space</span> <span style="color:grey">around</span> it: `Tiles.MaxFeatures`, 10,000, and `Tiles.Buffer`, 256, by <span style="color:grey">default</span>.
- <span style="color:grey">Whether</span> to <span style="color:grey">coin</span> Tessera's <span style="color:grey">own</span> `type` <span style="color:grey">addresses</span>, such as <span style="color:grey">one</span> for an <span style="color:grey">unknown</span> <span style="color:grey">layer</span>, or <span style="color:grey">keep</span> `about:blank`.

**Critical to success**

- **One shape for every error.** <span style="color:grey">Clients</span> <span style="color:grey">read</span> <span style="color:grey">each</span> <span style="color:grey">failure</span> the <span style="color:grey">same</span> <span style="color:grey">way</span>, so no <span style="color:grey">handler</span> <span style="color:grey">writes</span> an <span style="color:grey">error</span> <span style="color:grey">body</span> of its <span style="color:grey">own</span>.
- **The index must apply.** <span style="color:grey">Transform</span> the <span style="color:grey">tile</span>'s <span style="color:grey">box</span> into the <span style="color:grey">layer</span>'s SRID, <span style="color:grey">never</span> the <span style="color:grey">table</span>'s geometry into the <span style="color:grey">tile</span>'s, or every <span style="color:grey">tile</span> <span style="color:grey">reads</span> the <span style="color:grey">whole</span> <span style="color:grey">table</span>.


### Step 6 · S-01 Keep SQL out of every request

| | |
|---|---|
| Size | 2 <span style="color:grey">points</span> |
| Builds on | US-07: the <span style="color:grey">tile</span> <span style="color:grey">query</span> |

**In plain words.** **SQL injection** is an <span style="color:grey">attack</span> that <span style="color:grey">hides</span> SQL <span style="color:grey">inside</span> a <span style="color:grey">request</span>, such as a <span style="color:grey">layer</span> <span style="color:grey">named</span> `x; DROP TABLE cafes`, in the <span style="color:grey">hope</span> that the <span style="color:grey">database</span> <span style="color:grey">runs</span> it. <span style="color:grey">Two</span> <span style="color:grey">defences</span> <span style="color:grey">stop</span> it. <span style="color:grey">Each</span> <span style="color:grey">value</span> from the <span style="color:grey">request</span> <span style="color:grey">travels</span> <span style="color:grey">beside</span> the <span style="color:grey">query</span> as a **bound parameter**, <span style="color:grey">like</span> an <span style="color:grey">answer</span> <span style="color:grey">written</span> in a <span style="color:grey">form</span>'s <span style="color:grey">box</span>, so the <span style="color:grey">database</span> <span style="color:grey">never</span> <span style="color:grey">reads</span> it as SQL. And the <span style="color:grey">only</span> <span style="color:grey">names</span> that <span style="color:grey">enter</span> the SQL's <span style="color:grey">text</span> <span style="color:grey">come</span> from the catalogue (US-03), <span style="color:grey">quoted</span>.

> **Story.** **As** the <span style="color:grey">maintainer</span>, **I want** no <span style="color:grey">request</span> to <span style="color:grey">change</span> the SQL the <span style="color:grey">service</span> <span style="color:grey">sends</span>, **so that** no <span style="color:grey">office</span> <span style="color:grey">machine</span> can <span style="color:grey">read</span>, <span style="color:grey">change</span> or <span style="color:grey">drop</span> a <span style="color:grey">table</span> <span style="color:grey">through</span> the <span style="color:grey">tile</span> API.

**Acceptance criteria**

1. **Given** <span style="color:grey">any</span> <span style="color:grey">tile</span> <span style="color:grey">address</span>, **when** the <span style="color:grey">tile</span> <span style="color:grey">query</span> <span style="color:grey">runs</span>, **then** every <span style="color:grey">value</span> <span style="color:grey">reaches</span> the <span style="color:grey">database</span> as a <span style="color:grey">bound</span> ***parameter***, and a <span style="color:grey">property</span> <span style="color:grey">test</span> <span style="color:grey">proves</span> it.
2. **Given** <span style="color:grey">any</span> <span style="color:grey">query</span>, **then** its <span style="color:grey">text</span> <span style="color:grey">lives</span> in `Queries.cs`, the <span style="color:grey">one</span> <span style="color:grey">file</span> that <span style="color:grey">holds</span> SQL, and <span style="color:grey">only</span> `Database` <span style="color:grey">sends</span> it, <span style="color:grey">save</span> the <span style="color:grey">seed</span>'s journal schema (ADR 0009); a <span style="color:grey">search</span> at <span style="color:grey">each</span> <span style="color:grey">review</span> <span style="color:grey">finds</span> SQL <span style="color:grey">text</span> <span style="color:grey">nowhere</span> <span style="color:grey">else</span>.
3. **Given** a <span style="color:grey">table</span> or <span style="color:grey">column</span> <span style="color:grey">name</span> in a <span style="color:grey">query</span>, **then** it <span style="color:grey">comes</span> from the catalogue, <span style="color:grey">through</span> the <span style="color:grey">one</span> <span style="color:grey">function</span> that <span style="color:grey">quotes</span> <span style="color:grey">names</span> (US-03).
4. **Given** a <span style="color:grey">request</span> for a <span style="color:grey">layer</span> <span style="color:grey">named</span> `x; DROP TABLE cafes`, **then** the <span style="color:grey">service</span> <span style="color:grey">answers</span> 404, as a <span style="color:grey">problem</span> <span style="color:grey">document</span> (US-07), and every <span style="color:grey">table</span> <span style="color:grey">keeps</span> its <span style="color:grey">rows</span>.

**Tests to write first**

1. **Every address, one text.** A <span style="color:grey">property</span> <span style="color:grey">test</span>: for <span style="color:grey">any</span> <span style="color:grey">level</span>, <span style="color:grey">column</span> and <span style="color:grey">row</span>, the <span style="color:grey">tile</span> <span style="color:grey">query</span>'s <span style="color:grey">text</span> <span style="color:grey">equals</span> the <span style="color:grey">approved</span> <span style="color:grey">text</span>, and the <span style="color:grey">address</span> <span style="color:grey">travels</span> as <span style="color:grey">parameters</span> <span style="color:grey">alone</span>.
2. **The tile query's text.** It <span style="color:grey">matches</span> an <span style="color:grey">approved</span> snapshot, `approved/tile-query.sql`.
3. **An attack changes nothing.** <span style="color:grey">Through</span> the <span style="color:grey">real</span> <span style="color:grey">database</span>, <span style="color:grey">requests</span> for the <span style="color:grey">layers</span> `x; DROP TABLE cafes` and `food.cafes'; --` <span style="color:grey">each</span> <span style="color:grey">get</span> 404, and the <span style="color:grey">nine</span> <span style="color:grey">tables</span> <span style="color:grey">keep</span> their <span style="color:grey">rows</span>.

**Critical to success**

- **One file holds every SQL text.** A <span style="color:grey">reviewer</span> <span style="color:grey">reads</span> every <span style="color:grey">query</span> in <span style="color:grey">one</span> <span style="color:grey">place</span>, and a <span style="color:grey">search</span> <span style="color:grey">proves</span> no <span style="color:grey">other</span> <span style="color:grey">file</span> <span style="color:grey">holds</span> <span style="color:grey">one</span>.
- **Only the catalogue mints names.** The <span style="color:grey">layer</span> <span style="color:grey">name</span> in a <span style="color:grey">request</span> is a lookup <span style="color:grey">key</span>, <span style="color:grey">never</span> SQL: the <span style="color:grey">service</span> <span style="color:grey">finds</span> the <span style="color:grey">layer</span> in the catalogue, and <span style="color:grey">writes</span> the catalogue's <span style="color:grey">quoted</span> <span style="color:grey">name</span> into the <span style="color:grey">query</span>.

### Step 7 · S-06 Refuse malformed URLs

| | |
|---|---|
| Size | 1 <span style="color:grey">point</span> |
| Builds on | US-07: the <span style="color:grey">routes</span> and the <span style="color:grey">problem</span> <span style="color:grey">documents</span> |

**In plain words.** A **malformed URL** is an <span style="color:grey">address</span> disguised so that it <span style="color:grey">looks</span> <span style="color:grey">clean</span> <span style="color:grey">only</span> <span style="color:grey">after</span> a <span style="color:grey">web</span> <span style="color:grey">server</span> <span style="color:grey">tidies</span> it, such as a <span style="color:grey">path</span> that climbs <span style="color:grey">above</span> the <span style="color:grey">root</span>, or a `..` <span style="color:grey">hidden</span> as `%2e%2e`. Nginx <span style="color:grey">stands</span> in <span style="color:grey">front</span> of the <span style="color:grey">service</span> and <span style="color:grey">refuses</span> an <span style="color:grey">address</span> it <span style="color:grey">cannot</span> <span style="color:grey">read</span>. A disguised <span style="color:grey">address</span> that Nginx <span style="color:grey">passes</span> on <span style="color:grey">reaches</span> the <span style="color:grey">service</span> <span style="color:grey">exactly</span> as <span style="color:grey">sent</span>, so it <span style="color:grey">matches</span> no <span style="color:grey">route</span>.

> **Story.** **As** the <span style="color:grey">maintainer</span>, **I want** every <span style="color:grey">malformed</span> <span style="color:grey">request</span> <span style="color:grey">refused</span>, and every disguised <span style="color:grey">one</span> <span style="color:grey">left</span> unmatched, **so that** no <span style="color:grey">request</span> <span style="color:grey">reaches</span> a <span style="color:grey">route</span> in disguise.

**Acceptance criteria**

1. **Given** a <span style="color:grey">request</span> <span style="color:grey">target</span> that climbs <span style="color:grey">above</span> the <span style="color:grey">root</span>, <span style="color:grey">holds</span> a stray or invalid `%`, an <span style="color:grey">encoded</span> <span style="color:grey">null</span> (`%00`) or a <span style="color:grey">raw</span> <span style="color:grey">control</span> <span style="color:grey">character</span>, **then** Nginx <span style="color:grey">answers</span> 400 <span style="color:grey">before</span> the <span style="color:grey">service</span> <span style="color:grey">sees</span> it.
2. **Given** that 400, **then** its <span style="color:grey">body</span> is a <span style="color:grey">problem</span> <span style="color:grey">document</span> (US-07) whose `title` <span style="color:grey">reads</span> 'Bad Request', and it <span style="color:grey">never</span> <span style="color:grey">repeats</span> the <span style="color:grey">target</span>.
3. **Given** a disguised <span style="color:grey">target</span>, such as `%2e%2e`, an <span style="color:grey">encoded</span> <span style="color:grey">slash</span> (`%2F`) or a backslash, **then** it <span style="color:grey">matches</span> no <span style="color:grey">route</span>, and the <span style="color:grey">service</span> <span style="color:grey">answers</span> 404 as a <span style="color:grey">problem</span> <span style="color:grey">document</span>.
4. **Given** a <span style="color:grey">clean</span> <span style="color:grey">tile</span> <span style="color:grey">target</span>, **then** it <span style="color:grey">reaches</span> US-07's <span style="color:grey">route</span> <span style="color:grey">unchanged</span>.

**Tests to write first**

1. **Malformed targets are refused.** <span style="color:grey">Raw</span> <span style="color:grey">requests</span>, <span style="color:grey">written</span> <span style="color:grey">byte</span> for <span style="color:grey">byte</span> <span style="color:grey">through</span> Nginx, for <span style="color:grey">five</span> <span style="color:grey">malformed</span> or disguised <span style="color:grey">targets</span> <span style="color:grey">each</span> <span style="color:grey">get</span> 400 or 404, as a <span style="color:grey">problem</span> <span style="color:grey">document</span> that <span style="color:grey">hides</span> the <span style="color:grey">target</span>.
2. **The answer hides the target.** No 400 <span style="color:grey">body</span> <span style="color:grey">holds</span> <span style="color:grey">any</span> <span style="color:grey">part</span> of its <span style="color:grey">target</span>.
3. **A disguised address finds nothing.** The <span style="color:grey">service</span> <span style="color:grey">answers</span> an <span style="color:grey">unknown</span> <span style="color:grey">address</span> with a 404 <span style="color:grey">problem</span> <span style="color:grey">document</span>.
4. **Clean targets pass.** A <span style="color:grey">tile</span> <span style="color:grey">request</span> <span style="color:grey">through</span> Nginx <span style="color:grey">gets</span> 200.

**Open to talk**

- <span style="color:grey">Whether</span> Nginx should <span style="color:grey">refuse</span> the disguised <span style="color:grey">forms</span> with 400 <span style="color:grey">too</span>, <span style="color:grey">rather</span> than <span style="color:grey">leave</span> them to the <span style="color:grey">service</span>'s 404.

**Critical to success**

- **Never repair an address.** Nginx <span style="color:grey">refuses</span> what it <span style="color:grey">cannot</span> <span style="color:grey">read</span>, and the <span style="color:grey">service</span> <span style="color:grey">matches</span> <span style="color:grey">routes</span> on the <span style="color:grey">address</span> as <span style="color:grey">sent</span>; neither <span style="color:grey">tidies</span> a <span style="color:grey">path</span> into <span style="color:grey">one</span> that <span style="color:grey">matches</span>.

## Part C · Tiles that cost less

### Step 18 · N-19 Answer a kept tile without a query

**In plain words.** When `max-age` <span style="color:grey">passes</span>, the <span style="color:grey">browser</span> <span style="color:grey">asks</span> <span style="color:grey">again</span>, but it <span style="color:grey">still</span> <span style="color:grey">holds</span> its <span style="color:grey">copy</span>. **Acceptance criteria**

### Step 19 · N-20 Send tiles and the map's files packed

| | |
|---|---|
| Size | 1 <span style="color:grey">point</span> |
| Builds on | US-07: the <span style="color:grey">tile</span>; US-23: the <span style="color:grey">map</span>'s <span style="color:grey">files</span>; N-19: the ETag |

**In plain words.** The <span style="color:grey">map</span>'s <span style="color:grey">own</span> <span style="color:grey">code</span> is <span style="color:grey">about</span> a megabyte of JavaScript, and a <span style="color:grey">tile</span> is <span style="color:grey">some</span> kilobytes. Both shrink when **gzip** <span style="color:grey">packs</span> them: a <span style="color:grey">tile</span> by <span style="color:grey">about</span> <span style="color:grey">half</span>, <span style="color:grey">text</span> by <span style="color:grey">two</span> <span style="color:grey">thirds</span> or more. A <span style="color:grey">browser</span> <span style="color:grey">says</span> `Accept-Encoding: gzip` in every <span style="color:grey">request</span>; Nginx then <span style="color:grey">answers</span> with the <span style="color:grey">packed</span> <span style="color:grey">body</span> and `Content-Encoding: gzip`, and the <span style="color:grey">browser</span> unpacks it <span style="color:grey">before</span> it <span style="color:grey">reads</span> it.

> **Story.** **As** a <span style="color:grey">visitor</span>, **I want** the <span style="color:grey">map</span> and its <span style="color:grey">tiles</span> to <span style="color:grey">arrive</span> <span style="color:grey">packed</span>, **so that** the <span style="color:grey">map</span> <span style="color:grey">opens</span> <span style="color:grey">sooner</span> and <span style="color:grey">each</span> <span style="color:grey">pan</span> <span style="color:grey">costs</span> the <span style="color:grey">network</span> <span style="color:grey">less</span>.

**Acceptance criteria**

1. **Given** a <span style="color:grey">request</span> with `Accept-Encoding: gzip` for a <span style="color:grey">tile</span>, the <span style="color:grey">page</span> or <span style="color:grey">one</span> of the <span style="color:grey">map</span>'s <span style="color:grey">files</span>, **when** the <span style="color:grey">answer</span> is 200, **then** its <span style="color:grey">body</span> is gzip-packed, it <span style="color:grey">carries</span> `Content-Encoding: gzip`, and the unpacked <span style="color:grey">bytes</span> <span style="color:grey">equal</span> the <span style="color:grey">plain</span> <span style="color:grey">answer</span>'s.
2. **Given** a <span style="color:grey">request</span> <span style="color:grey">without</span> `Accept-Encoding`, **then** the <span style="color:grey">body</span> <span style="color:grey">travels</span> <span style="color:grey">plain</span>, with no `Content-Encoding`.
3. **Given** either <span style="color:grey">answer</span>, **then** it <span style="color:grey">carries</span> `Vary: Accept-Encoding`, so no <span style="color:grey">browser</span> or proxy <span style="color:grey">hands</span> a <span style="color:grey">packed</span> <span style="color:grey">body</span> to a <span style="color:grey">client</span> that <span style="color:grey">asked</span> for <span style="color:grey">plain</span>.
4. **Given** a 304 (N-19), **then** the ***weak ETag*** <span style="color:grey">matches</span> whichever <span style="color:grey">form</span> the <span style="color:grey">browser</span> <span style="color:grey">holds</span>, <span style="color:grey">since</span> both <span style="color:grey">forms</span> are the <span style="color:grey">same</span> <span style="color:grey">tile</span>.

**Tests to write first**
