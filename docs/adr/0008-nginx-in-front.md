# ADR 0008: Put Nginx in front of the service

| | |
|---|---|
| Status | <span style="color:grey">Accepted</span> |
| Date | 14 <span style="color:grey">October</span> 2026 |
| Decider | The <span style="color:grey">maintainer</span> |
| Covers | The <span style="color:grey">service</span>, `nathanwh71/Tessera`, and the Nginx in <span style="color:grey">front</span> of it |
| Related | ADR 0003; ADR 0006; ADR 0007; US-35, S-06, S-07, S-30, N-18 to N-20, N-23, N-24, N-28, N-29 |

## Decision

Nginx <span style="color:grey">stands</span> in <span style="color:grey">front</span> of the <span style="color:grey">service</span>. It <span style="color:grey">answers</span> the <span style="color:grey">office</span> on <span style="color:grey">port</span> 80, and the <span style="color:grey">office</span> <span style="color:grey">alone</span>, and <span style="color:grey">shares</span> the <span style="color:grey">requests</span> <span style="color:grey">between</span> <span style="color:grey">two</span> <span style="color:grey">copies</span> of the <span style="color:grey">service</span> on 127.0.0.1, <span style="color:grey">ports</span> 7800 and 7801 (N-29). It <span style="color:grey">caps</span> what <span style="color:grey">each</span> <span style="color:grey">office</span> <span style="color:grey">machine</span> may <span style="color:grey">ask</span> (ADR 0007), <span style="color:grey">keeps</span> ***tiles***, <span style="color:grey">packs</span> <span style="color:grey">answers</span> with gzip, <span style="color:grey">answers</span> 304, <span style="color:grey">lets</span> <span style="color:grey">one</span> <span style="color:grey">query</span> <span style="color:grey">build</span> a <span style="color:grey">tile</span> that <span style="color:grey">many</span> <span style="color:grey">people</span> <span style="color:grey">ask</span> for at <span style="color:grey">once</span>, <span style="color:grey">refuses</span> <span style="color:grey">malformed</span> <span style="color:grey">addresses</span>, and <span style="color:grey">serves</span> the <span style="color:grey">tiles</span> it <span style="color:grey">holds</span> <span style="color:grey">while</span> the <span style="color:grey">service</span> or the <span style="color:grey">database</span> is <span style="color:grey">down</span>. The <span style="color:grey">service</span> <span style="color:grey">keeps</span> no <span style="color:grey">code</span> for those <span style="color:grey">jobs</span>. <span style="color:grey">One</span> <span style="color:grey">copy</span> of Nginx <span style="color:grey">runs</span> in <span style="color:grey">front</span> of the <span style="color:grey">two</span> <span style="color:grey">copies</span> of the <span style="color:grey">service</span>.

## Why

<span style="color:grey">Caching</span>, packing and <span style="color:grey">watching</span> a <span style="color:grey">server</span> are Nginx's daily <span style="color:grey">work</span>, <span style="color:grey">tested</span> on millions of <span style="color:grey">sites</span>. <span style="color:grey">Handing</span> those <span style="color:grey">jobs</span> to Nginx <span style="color:grey">keeps</span> the <span style="color:grey">service</span> <span style="color:grey">small</span> <span style="color:grey">enough</span> for <span style="color:grey">one</span> <span style="color:grey">maintainer</span> to <span style="color:grey">read</span>: it <span style="color:grey">serves</span> <span style="color:grey">tiles</span>, the <span style="color:grey">map</span> and `/health`, and <span style="color:grey">little</span> <span style="color:grey">else</span>.

## What Nginx does

| Job | How Nginx does it |
|---|---|
| Keep a tile for as long as `Cache-Control` allows, within 64 MB | `proxy_cache`, with `max_size=64m` |
| Let one query serve many people who ask for one new tile | `proxy_cache_lock` |
| Pack answers with gzip, and say `Vary: Accept-Encoding` | `gzip`, `gzip_vary` |
| Answer 304 to a browser that sends the tag back | Its <span style="color:grey">own</span> <span style="color:grey">check</span> of `If-None-Match` <span style="color:grey">against</span> the <span style="color:grey">stored</span> `ETag` |
| Serve kept tiles while the service or the database is down, and an expired tile while a fresh copy is fetched behind it | `proxy_cache_use_stale`, `proxy_cache_background_update` |
| Refuse a malformed address, with a problem document that hides it | Its <span style="color:grey">own</span> parser, and `error_page 400` |
| Send a request to the other copy when one crashes or hangs, and rest the failed copy | `proxy_next_upstream error timeout`, `max_fails=3 fail_timeout=10s` |

The <span style="color:grey">service</span> <span style="color:grey">sends</span> `Cache-Control` and a <span style="color:grey">weak</span> `ETag` with <span style="color:grey">each</span> <span style="color:grey">tile</span>, <span style="color:grey">answers</span> `/health`, and <span style="color:grey">writes</span> its <span style="color:grey">own</span> ***problem documents***.

## A passive health check over two copies

Nginx's <span style="color:grey">free</span> <span style="color:grey">edition</span> <span style="color:grey">watches</span> a <span style="color:grey">server</span> <span style="color:grey">only</span> <span style="color:grey">through</span> the <span style="color:grey">requests</span> it <span style="color:grey">passes</span> on: <span style="color:grey">three</span> <span style="color:grey">failures</span> <span style="color:grey">within</span> <span style="color:grey">ten</span> <span style="color:grey">seconds</span> <span style="color:grey">rest</span> the <span style="color:grey">server</span> for <span style="color:grey">ten</span>, and a <span style="color:grey">failed</span> <span style="color:grey">request</span> <span style="color:grey">goes</span> on to the <span style="color:grey">other</span> <span style="color:grey">copy</span>. With a <span style="color:grey">single</span> <span style="color:grey">server</span> in the <span style="color:grey">group</span>, Nginx would <span style="color:grey">ignore</span> both <span style="color:grey">numbers</span>, so `npm start` <span style="color:grey">runs</span> <span style="color:grey">two</span> <span style="color:grey">copies</span> and <span style="color:grey">starts</span> <span style="color:grey">again</span> <span style="color:grey">any</span> <span style="color:grey">copy</span> that <span style="color:grey">stops</span> (N-29). Both <span style="color:grey">copies</span> <span style="color:grey">run</span> on <span style="color:grey">one</span> <span style="color:grey">machine</span>, so they <span style="color:grey">guard</span> <span style="color:grey">against</span> a <span style="color:grey">failed</span> <span style="color:grey">program</span>, not a <span style="color:grey">failed</span> <span style="color:grey">machine</span>. <span style="color:grey">Only</span> a <span style="color:grey">crash</span> or a <span style="color:grey">hang</span> <span style="color:grey">counts</span> as a <span style="color:grey">failure</span> (`proxy_next_upstream error timeout`), so a <span style="color:grey">database</span> <span style="color:grey">outage</span>, which every <span style="color:grey">copy</span> <span style="color:grey">shares</span>, <span style="color:grey">never</span> <span style="color:grey">rests</span> a <span style="color:grey">healthy</span> <span style="color:grey">copy</span>. Active <span style="color:grey">checks</span>, which <span style="color:grey">ask</span> `/health` on a timer, <span style="color:grey">need</span> NGINX Plus.

## How it runs

`npm start` <span style="color:grey">runs</span> Nginx in Docker, on the <span style="color:grey">machine</span>'s <span style="color:grey">own</span> <span style="color:grey">network</span>, from `nginx/default.conf.template`; the <span style="color:grey">image</span> <span style="color:grey">fills</span> in `TESSERA_HTTPPORT`, `TESSERA_OFFICE_NETWORK` and the <span style="color:grey">two</span> <span style="color:grey">copies</span>' <span style="color:grey">ports</span>, `TESSERA_SERVICE_PORT` and `TESSERA_SECOND_SERVICE_PORT`, as it <span style="color:grey">starts</span>. Nginx <span style="color:grey">runs</span> as <span style="color:grey">root</span> <span style="color:grey">inside</span> its <span style="color:grey">container</span>, so <span style="color:grey">port</span> 80 <span style="color:grey">needs</span> no <span style="color:grey">change</span> to Ubuntu's <span style="color:grey">limit</span> on <span style="color:grey">low</span> <span style="color:grey">ports</span>. The ***browser tests*** <span style="color:grey">run</span> <span style="color:grey">through</span> Nginx, and `scripts/lib/edge.ts` then <span style="color:grey">checks</span> what it <span style="color:grey">adds</span>: the <span style="color:grey">office</span> <span style="color:grey">rule</span> and the <span style="color:grey">rate</span> for <span style="color:grey">each</span> <span style="color:grey">machine</span>, <span style="color:grey">kept</span> <span style="color:grey">tiles</span>, 304, gzip, <span style="color:grey">HEAD</span>, <span style="color:grey">malformed</span> <span style="color:grey">addresses</span>, the <span style="color:grey">second</span> <span style="color:grey">copy</span> <span style="color:grey">taking</span> over when the <span style="color:grey">first</span> <span style="color:grey">stops</span>, and <span style="color:grey">tiles</span> <span style="color:grey">served</span> with both <span style="color:grey">stopped</span>.

## Options considered

| Option | Why not |
|---|---|
| A cache in the service, of its own or on `MemoryCache` | It <span style="color:grey">puts</span> <span style="color:grey">code</span> in the <span style="color:grey">service</span> that Nginx <span style="color:grey">already</span> has, and `MemoryCache` <span style="color:grey">turns</span> a <span style="color:grey">new</span> <span style="color:grey">tile</span> <span style="color:grey">away</span> when it is <span style="color:grey">full</span> |
| YARP, a proxy written in .NET | <span style="color:grey">One</span> more <span style="color:grey">program</span> of our <span style="color:grey">own</span>, <span style="color:grey">set</span> <span style="color:grey">up</span> in <span style="color:grey">code</span>; Nginx <span style="color:grey">needs</span> <span style="color:grey">one</span> <span style="color:grey">file</span> of 121 <span style="color:grey">lines</span> |
| Varnish | A ***cache*** <span style="color:grey">alone</span>: no gzip of its <span style="color:grey">own</span>, no <span style="color:grey">answer</span> to a <span style="color:grey">malformed</span> <span style="color:grey">address</span>, and a <span style="color:grey">language</span> of its <span style="color:grey">own</span> for its <span style="color:grey">rules</span> |

## Consequences

- A withdrawn ***layer***'s <span style="color:grey">tiles</span> <span style="color:grey">stay</span> in Nginx for <span style="color:grey">up</span> to `Tiles.CacheSeconds`, 60 by <span style="color:grey">default</span>, as they <span style="color:grey">already</span> <span style="color:grey">stay</span> in <span style="color:grey">browsers</span>; the <span style="color:grey">free</span> <span style="color:grey">edition</span> <span style="color:grey">cannot</span> <span style="color:grey">clear</span> <span style="color:grey">one</span> <span style="color:grey">layer</span> on <span style="color:grey">demand</span> (N-23 c3).
- A <span style="color:grey">tile</span> Nginx has <span style="color:grey">never</span> <span style="color:grey">held</span>, <span style="color:grey">asked</span> for <span style="color:grey">while</span> both <span style="color:grey">copies</span> are <span style="color:grey">down</span>, <span style="color:grey">answers</span> 503 with `Retry-After: 5`.
- <span style="color:grey">Two</span> <span style="color:grey">copies</span> <span style="color:grey">hold</span> <span style="color:grey">two</span> <span style="color:grey">pools</span> of <span style="color:grey">database</span> <span style="color:grey">connections</span>, 8 in all by <span style="color:grey">default</span>.
- <span style="color:grey">One</span> more <span style="color:grey">program</span> <span style="color:grey">runs</span> in production, and its <span style="color:grey">file</span> must be <span style="color:grey">read</span> <span style="color:grey">beside</span> the <span style="color:grey">service</span>'s.

## When to revisit

- The <span style="color:grey">office</span> <span style="color:grey">needs</span> the <span style="color:grey">service</span> to <span style="color:grey">survive</span> a <span style="color:grey">failed</span> <span style="color:grey">machine</span>: a <span style="color:grey">second</span> <span style="color:grey">machine</span>, with Nginx's `upstream` <span style="color:grey">group</span> <span style="color:grey">listing</span> its <span style="color:grey">copies</span> <span style="color:grey">too</span>.
- A <span style="color:grey">layer</span> must vanish at <span style="color:grey">once</span> when its ***grant*** is withdrawn: NGINX Plus, or a ***module*** that <span style="color:grey">clears</span> the <span style="color:grey">cache</span>.
