# ADR 0001: Build the back end as a modular monolith, with the compiler guarding its borders

| | |
|---|---|
| Status | <span style="color:grey">Accepted</span> |
| Date | 15 <span style="color:grey">October</span> 2026 |
| Decider | The <span style="color:grey">maintainer</span> |
| Covers | The <span style="color:grey">Phase</span> Oct <span style="color:grey">back</span> <span style="color:grey">end</span>, in C# 14 on .NET 10, in `nathanwh71/Tessera` |
| Stories | US-00, US-01, US-03, US-24, US-07, S-01, S-06, US-35, US-23 (`docs/user-stories/user-stories.md`) |

## Decision

Tessera's <span style="color:grey">back</span> <span style="color:grey">end</span> is <span style="color:grey">one</span> <span style="color:grey">service</span>, <span style="color:grey">built</span> and <span style="color:grey">shipped</span> as <span style="color:grey">one</span> <span style="color:grey">unit</span>, and <span style="color:grey">divided</span> <span style="color:grey">inside</span> into ***modules*** with <span style="color:grey">fixed</span> <span style="color:grey">borders</span>. <span style="color:grey">Each</span> <span style="color:grey">module</span> is a <span style="color:grey">project</span> of its <span style="color:grey">own</span>, in a <span style="color:grey">folder</span> of `src/Tessera`, and <span style="color:grey">names</span> <span style="color:grey">only</span> the <span style="color:grey">modules</span> it may <span style="color:grey">use</span>. The <span style="color:grey">compiler</span> <span style="color:grey">guards</span> the <span style="color:grey">borders</span>: a <span style="color:grey">module</span> that <span style="color:grey">reaches</span> into <span style="color:grey">one</span> it does not <span style="color:grey">name</span>, or a <span style="color:grey">circle</span> of <span style="color:grey">modules</span>, <span style="color:grey">fails</span> the <span style="color:grey">build</span>.

This <span style="color:grey">record</span> <span style="color:grey">covers</span> the <span style="color:grey">back</span> <span style="color:grey">end</span> <span style="color:grey">alone</span>. The <span style="color:grey">map</span>'s <span style="color:grey">front</span> <span style="color:grey">end</span>, in TypeScript, <span style="color:grey">keeps</span> its <span style="color:grey">own</span> <span style="color:grey">design</span> (ADR 0006).

## Context

<span style="color:grey">Five</span> <span style="color:grey">facts</span> <span style="color:grey">shape</span> the <span style="color:grey">decision</span>.

- **One maintainer.** <span style="color:grey">One</span> <span style="color:grey">person</span> <span style="color:grey">builds</span>, <span style="color:grey">runs</span> and <span style="color:grey">repairs</span> Tessera, and should not have to <span style="color:grey">remember</span> which <span style="color:grey">module</span> may <span style="color:grey">use</span> which.
- **One machine.** The <span style="color:grey">service</span> <span style="color:grey">runs</span> in Ubuntu 24.04 <span style="color:grey">inside</span> WSL2, on <span style="color:grey">one</span> <span style="color:grey">Windows</span> 11 <span style="color:grey">machine</span>, <span style="color:grey">behind</span> Nginx on <span style="color:grey">port</span> 80 (US-35, ADR 0008).
- **One program.** The <span style="color:grey">same</span> <span style="color:grey">service</span> <span style="color:grey">serves</span> the ***tiles*** (US-07) and the <span style="color:grey">map</span>'s <span style="color:grey">files</span> (US-23), and <span style="color:grey">ships</span> them in <span style="color:grey">one</span> <span style="color:grey">release</span>; `npm start` <span style="color:grey">runs</span> <span style="color:grey">two</span> <span style="color:grey">copies</span> of it <span style="color:grey">behind</span> Nginx (N-29).
- **One gate to the database.** S-01 <span style="color:grey">requires</span> that every SQL <span style="color:grey">text</span> <span style="color:grey">lives</span> in <span style="color:grey">one</span> <span style="color:grey">file</span> and that the <span style="color:grey">service</span> <span style="color:grey">sends</span> it <span style="color:grey">through</span> <span style="color:grey">one</span> <span style="color:grey">module</span>.
- **One place for the design.** The <span style="color:grey">stories</span> <span style="color:grey">leave</span> the <span style="color:grey">design</span> to the <span style="color:grey">team</span> on <span style="color:grey">purpose</span>; this <span style="color:grey">record</span> <span style="color:grey">holds</span> it.

## Options considered

| Option | For | Against |
|---|---|---|
| A project for each module, in the folders of one service (chosen) | The <span style="color:grey">compiler</span> <span style="color:grey">guards</span> every <span style="color:grey">border</span>, and the <span style="color:grey">folders</span> <span style="color:grey">read</span> as <span style="color:grey">one</span> <span style="color:grey">program</span>. A <span style="color:grey">module</span>'s <span style="color:grey">file</span> <span style="color:grey">names</span> its every <span style="color:grey">neighbour</span>. | <span style="color:grey">Eight</span> <span style="color:grey">project</span> <span style="color:grey">files</span> to <span style="color:grey">keep</span>, <span style="color:grey">each</span> a <span style="color:grey">few</span> <span style="color:grey">lines</span>. |
| One project, a folder for each module | <span style="color:grey">One</span> <span style="color:grey">file</span> to <span style="color:grey">build</span>. | <span style="color:grey">Nothing</span> but <span style="color:grey">review</span> <span style="color:grey">guards</span> the <span style="color:grey">borders</span>, so a <span style="color:grey">circle</span> of <span style="color:grey">modules</span> can <span style="color:grey">grow</span> unnoticed. |
| An architecture test that reads the code | <span style="color:grey">One</span> <span style="color:grey">project</span>, and a <span style="color:grey">failing</span> <span style="color:grey">test</span> for a <span style="color:grey">break</span>. | A <span style="color:grey">text</span> <span style="color:grey">test</span> misses <span style="color:grey">some</span> <span style="color:grey">routes</span> <span style="color:grey">round</span> it; a <span style="color:grey">test</span> <span style="color:grey">library</span>, such as ArchUnitNET, <span style="color:grey">adds</span> a <span style="color:grey">dependency</span>. |
| Separate services | The <span style="color:grey">network</span> <span style="color:grey">enforces</span> the <span style="color:grey">borders</span>. | <span style="color:grey">Several</span> <span style="color:grey">releases</span> on <span style="color:grey">one</span> <span style="color:grey">machine</span>, and <span style="color:grey">network</span> <span style="color:grey">calls</span> <span style="color:grey">between</span> <span style="color:grey">parts</span>, for <span style="color:grey">one</span> <span style="color:grey">maintainer</span> who <span style="color:grey">gains</span> <span style="color:grey">nothing</span> from them. |

## The modules

| Project | Owns | May use | Stories |
|---|---|---|---|
| `Tessera.Problems` | The <span style="color:grey">shape</span> of every ***problem document*** | <span style="color:grey">Nothing</span> | US-07 |
| `Tessera.Settings` | <span style="color:grey">Reading</span> `tessera.json` and the <span style="color:grey">environment</span>, and <span style="color:grey">refusing</span> to <span style="color:grey">start</span> when a <span style="color:grey">value</span> is <span style="color:grey">wrong</span> (ADR 0003) | <span style="color:grey">Nothing</span> | US-00 |
| `Tessera.Sql` | Every <span style="color:grey">query</span>'s <span style="color:grey">text</span>, in `Queries.cs`; the <span style="color:grey">database</span>'s URL; the <span style="color:grey">one</span> <span style="color:grey">pool</span> and the <span style="color:grey">one</span> <span style="color:grey">class</span>, `Database`, that <span style="color:grey">sends</span> <span style="color:grey">queries</span> <span style="color:grey">through</span> Npgsql with Dapper | <span style="color:grey">Settings</span> | S-01, US-03 |
| `Tessera.Catalogue` | The <span style="color:grey">list</span> of <span style="color:grey">granted</span> <span style="color:grey">tables</span> and <span style="color:grey">views</span>, <span style="color:grey">read</span> at start-up and <span style="color:grey">again</span> every `Catalogue.RefreshSeconds` | Sql | US-03, N-23 |
| `Tessera.Seeding` | The `seed` <span style="color:grey">command</span>: DbUp <span style="color:grey">runs</span> <span style="color:grey">each</span> <span style="color:grey">new</span> <span style="color:grey">script</span> in `db/seed` <span style="color:grey">once</span>, as `tessera_publisher` (ADR 0009) | Sql | US-24 |
| `Tessera.Tiles` | The <span style="color:grey">tile</span> <span style="color:grey">route</span>, the ***tile query***'s <span style="color:grey">inputs</span>, and the <span style="color:grey">headers</span> that <span style="color:grey">let</span> a <span style="color:grey">browser</span> and Nginx <span style="color:grey">keep</span> a <span style="color:grey">tile</span> | ***Catalogue***, <span style="color:grey">Settings</span>, Sql, <span style="color:grey">Problems</span> | US-07, N-18 |
| `Tessera.Map` | <span style="color:grey">Serving</span> the <span style="color:grey">front</span> <span style="color:grey">end</span>'s <span style="color:grey">built</span> <span style="color:grey">files</span>, and <span style="color:grey">writing</span> the <span style="color:grey">area</span> into its <span style="color:grey">page</span> | <span style="color:grey">Settings</span>, <span style="color:grey">Problems</span> | US-23 |

`Tessera`, the <span style="color:grey">program</span>, <span style="color:grey">holds</span> `Program.cs` and `Service.cs`. It <span style="color:grey">names</span> every <span style="color:grey">module</span>, <span style="color:grey">puts</span> them <span style="color:grey">together</span>, and is the <span style="color:grey">only</span> <span style="color:grey">project</span> that <span style="color:grey">ships</span>. No <span style="color:grey">module</span> <span style="color:grey">names</span> it.

A <span style="color:grey">module</span> <span style="color:grey">joins</span> the <span style="color:grey">list</span> when a <span style="color:grey">story</span> <span style="color:grey">needs</span> <span style="color:grey">one</span>, and <span style="color:grey">leaves</span> when <span style="color:grey">none</span> does.

**The seed is a command of the service.** The <span style="color:grey">same</span> <span style="color:grey">program</span> that <span style="color:grey">serves</span> <span style="color:grey">tiles</span> <span style="color:grey">runs</span> the <span style="color:grey">seed</span> when <span style="color:grey">called</span> with `seed`, then <span style="color:grey">stops</span>. Its <span style="color:grey">checks</span> and its <span style="color:grey">tests</span> <span style="color:grey">live</span> in C#, <span style="color:grey">beside</span> the <span style="color:grey">rest</span> of the <span style="color:grey">back</span> <span style="color:grey">end</span>.

**Each program signs in as its own role.** The <span style="color:grey">service</span> <span style="color:grey">signs</span> in as `tessera_reader`, which <span style="color:grey">reads</span> <span style="color:grey">granted</span> <span style="color:grey">tables</span> <span style="color:grey">alone</span> (US-03). The <span style="color:grey">seed</span> <span style="color:grey">signs</span> in as `tessera_publisher`, the <span style="color:grey">data</span> <span style="color:grey">publisher</span>'s ***role***, which <span style="color:grey">owns</span> the ***schemas*** and their <span style="color:grey">tables</span>. It <span style="color:grey">creates</span> and <span style="color:grey">fills</span> them; the <span style="color:grey">publisher</span> ***grants*** them when <span style="color:grey">ready</span> (US-24, <span style="color:grey">criterion</span> 5).

| Variable | Read by | Holds |
|---|---|---|
| `DATABASE_URL` | The <span style="color:grey">service</span>, at every <span style="color:grey">start</span> | `postgresql://tessera_reader:<password>@<host>:<port>/<database>` |
| `TESSERA_PUBLISHER_DATABASE_URL` | `seed`, <span style="color:grey">only</span> when it <span style="color:grey">runs</span> | `postgresql://tessera_publisher:<password>@<host>:<port>/<database>` |
| `TESSERA_READER_PASSWORD` | The <span style="color:grey">role</span> <span style="color:grey">script</span>, on the <span style="color:grey">database</span>'s <span style="color:grey">first</span> <span style="color:grey">start</span> | `tessera_reader`'s <span style="color:grey">password</span> |
| `TESSERA_PUBLISHER_PASSWORD` | The <span style="color:grey">role</span> <span style="color:grey">script</span>, on the <span style="color:grey">database</span>'s <span style="color:grey">first</span> <span style="color:grey">start</span> | `tessera_publisher`'s <span style="color:grey">password</span> |

<span style="color:grey">Each</span> URL <span style="color:grey">carries</span> the <span style="color:grey">machine</span>'s <span style="color:grey">name</span>, <span style="color:grey">address</span> and <span style="color:grey">port</span>, as US-00 <span style="color:grey">requires</span>; `Sql` <span style="color:grey">turns</span> it into a <span style="color:grey">connection</span> <span style="color:grey">string</span> for the <span style="color:grey">database</span> <span style="color:grey">client</span>. The <span style="color:grey">service</span> <span style="color:grey">never</span> <span style="color:grey">reads</span> `TESSERA_PUBLISHER_DATABASE_URL`, so it <span style="color:grey">never</span> <span style="color:grey">holds</span> the <span style="color:grey">publisher</span>'s <span style="color:grey">rights</span> <span style="color:grey">while</span> it <span style="color:grey">serves</span> <span style="color:grey">tiles</span>.

**`npm start` runs the seed at every start.** The <span style="color:grey">script</span> <span style="color:grey">starts</span> the <span style="color:grey">database</span>, <span style="color:grey">waits</span> until it <span style="color:grey">answers</span>, and <span style="color:grey">runs</span> `seed`. DbUp <span style="color:grey">runs</span> <span style="color:grey">only</span> the <span style="color:grey">scripts</span> it has not <span style="color:grey">run</span> <span style="color:grey">before</span>, so a <span style="color:grey">start</span> with <span style="color:grey">nothing</span> <span style="color:grey">new</span> <span style="color:grey">changes</span> <span style="color:grey">nothing</span>.

## Rules at the borders, and what guards each

| Rule | Guard |
|---|---|
| 1. **A small public face.** Each module shows only the types other modules need. | The <span style="color:grey">compiler</span>: an `internal` <span style="color:grey">type</span> <span style="color:grey">stays</span> <span style="color:grey">inside</span> its <span style="color:grey">project</span>. |
| 2. **One direction.** Modules depend on one another in one direction, with no circle. | The <span style="color:grey">compiler</span>: .NET <span style="color:grey">refuses</span> a <span style="color:grey">circle</span> of <span style="color:grey">project</span> <span style="color:grey">references</span>. |
| 3. **Named neighbours alone.** A module uses only the modules its project file names. | The <span style="color:grey">compiler</span>: `DisableTransitiveProjectReferences`, <span style="color:grey">set</span> in `src/Tessera/Directory.Build.props`, <span style="color:grey">stops</span> a <span style="color:grey">module</span> <span style="color:grey">seeing</span>, <span style="color:grey">say</span>, <span style="color:grey">Settings</span> <span style="color:grey">through</span> Sql. |
| 4. **One gate to SQL.** Every SQL text lives in `Queries.cs`, and only `Database` sends it, save the seed, which sends the journal's schema through a connection of its own (S-01, criterion 2; ADR 0009). | The <span style="color:grey">compiler</span>: `Tessera.Sql` <span style="color:grey">names</span> Npgsql and Dapper, <span style="color:grey">each</span> <span style="color:grey">marked</span> `PrivateAssets="compile;contentfiles;analyzers;build"`, so no <span style="color:grey">project</span> that <span style="color:grey">names</span> Sql can <span style="color:grey">use</span> them; their <span style="color:grey">files</span> <span style="color:grey">still</span> <span style="color:grey">reach</span> the <span style="color:grey">finished</span> <span style="color:grey">service</span>. `Tessera.Seeding` is the <span style="color:grey">one</span> <span style="color:grey">other</span> <span style="color:grey">door</span>: it <span style="color:grey">reaches</span> Npgsql <span style="color:grey">through</span> DbUp, and <span style="color:grey">opens</span> <span style="color:grey">one</span> <span style="color:grey">connection</span> of its <span style="color:grey">own</span> to <span style="color:grey">make</span> DbUp's ***journal*** schema, with the <span style="color:grey">text</span> from `Queries.cs` (ADR 0009). |
| 5. **One shape for errors.** Every problem document takes its shape from `Tessera.Problems`; no route writes an error body of its own (US-07). | <span style="color:grey">Review</span>. |
| 6. **Values, not shared state.** Modules pass immutable values to one another, and report an expected failure as a `Result`, never as a shared object or an exception (ADR 0004). | <span style="color:grey">Review</span>. |

The <span style="color:grey">tile</span> <span style="color:grey">query</span> <span style="color:grey">shows</span> <span style="color:grey">rule</span> 2 at <span style="color:grey">work</span>. `Queries.Tile` <span style="color:grey">takes</span> a `TileSource`, a <span style="color:grey">record</span> of `Sql`'s <span style="color:grey">own</span>, and <span style="color:grey">plain</span> <span style="color:grey">numbers</span> for the <span style="color:grey">tile</span>, so `Sql` <span style="color:grey">needs</span> <span style="color:grey">nothing</span> of `Catalogue`'s or `Tiles`'. `Catalogue`'s `Layer` <span style="color:grey">hands</span> over its `Source`.

## Consequences

**What gets easier**

- A <span style="color:grey">break</span> of <span style="color:grey">rules</span> 2, 3 or 4 <span style="color:grey">fails</span> the <span style="color:grey">build</span> at <span style="color:grey">once</span>, with the <span style="color:grey">compiler</span>'s <span style="color:grey">own</span> <span style="color:grey">message</span>.
- <span style="color:grey">Each</span> <span style="color:grey">module</span>'s <span style="color:grey">project</span> <span style="color:grey">file</span> <span style="color:grey">lists</span> its <span style="color:grey">neighbours</span>, so the <span style="color:grey">design</span> <span style="color:grey">reads</span> from <span style="color:grey">eight</span> <span style="color:grey">short</span> <span style="color:grey">files</span>.
- <span style="color:grey">Each</span> <span style="color:grey">story</span> <span style="color:grey">changes</span> <span style="color:grey">one</span> or <span style="color:grey">two</span> <span style="color:grey">modules</span>, so its <span style="color:grey">tests</span> <span style="color:grey">stay</span> <span style="color:grey">small</span>.
- <span style="color:grey">One</span> <span style="color:grey">release</span> <span style="color:grey">keeps</span> US-35's set-up <span style="color:grey">simple</span>: <span style="color:grey">one</span> <span style="color:grey">program</span> <span style="color:grey">behind</span> Nginx.
- A <span style="color:grey">module</span> that <span style="color:grey">later</span> <span style="color:grey">needs</span> its <span style="color:grey">own</span> <span style="color:grey">machine</span> can <span style="color:grey">leave</span> along a <span style="color:grey">border</span> that <span style="color:grey">already</span> <span style="color:grey">exists</span>.

**What gets harder**

- <span style="color:grey">Each</span> <span style="color:grey">story</span> <span style="color:grey">begins</span> with a <span style="color:grey">decision</span>: which <span style="color:grey">module</span> <span style="color:grey">owns</span> the <span style="color:grey">new</span> <span style="color:grey">code</span>.
- A <span style="color:grey">new</span> <span style="color:grey">use</span> of <span style="color:grey">one</span> <span style="color:grey">module</span> by another <span style="color:grey">needs</span> a <span style="color:grey">line</span> in a <span style="color:grey">project</span> <span style="color:grey">file</span>, and a <span style="color:grey">moment</span>'s <span style="color:grey">thought</span> <span style="color:grey">about</span> <span style="color:grey">whether</span> it <span style="color:grey">belongs</span>.
- The <span style="color:grey">release</span> <span style="color:grey">holds</span> <span style="color:grey">one</span> <span style="color:grey">file</span> for <span style="color:grey">each</span> <span style="color:grey">module</span>, <span style="color:grey">seven</span> in all, <span style="color:grey">beside</span> the <span style="color:grey">program</span>'s <span style="color:grey">own</span>.

## When to revisit

The ***modular monolith*** <span style="color:grey">stands</span> until <span style="color:grey">one</span> of <span style="color:grey">three</span> <span style="color:grey">events</span> <span style="color:grey">happens</span>. <span style="color:grey">Each</span> <span style="color:grey">reopens</span> the <span style="color:grey">decision</span>.

- **A part needs its own machine.** If <span style="color:grey">tiles</span> <span style="color:grey">draw</span> so <span style="color:grey">many</span> <span style="color:grey">requests</span> that the <span style="color:grey">tile</span> <span style="color:grey">work</span> <span style="color:grey">needs</span> a <span style="color:grey">second</span> <span style="color:grey">machine</span> <span style="color:grey">while</span> the <span style="color:grey">rest</span> <span style="color:grey">stays</span> <span style="color:grey">put</span>, `Tessera.Tiles` may <span style="color:grey">leave</span> as a <span style="color:grey">separate</span> <span style="color:grey">service</span>.
- **A part needs its own release.** If the <span style="color:grey">map</span> must <span style="color:grey">ship</span> <span style="color:grey">changes</span> <span style="color:grey">weekly</span> <span style="color:grey">while</span> the <span style="color:grey">tile</span> API <span style="color:grey">changes</span> <span style="color:grey">twice</span> a <span style="color:grey">year</span>, <span style="color:grey">one</span> <span style="color:grey">release</span> for both <span style="color:grey">starts</span> to <span style="color:grey">hurt</span>.
- **A second maintainer joins.** If <span style="color:grey">two</span> <span style="color:grey">people</span> <span style="color:grey">each</span> <span style="color:grey">own</span> <span style="color:grey">part</span> of the <span style="color:grey">back</span> <span style="color:grey">end</span>, <span style="color:grey">separate</span> <span style="color:grey">services</span> may <span style="color:grey">suit</span> them <span style="color:grey">better</span>.

In <span style="color:grey">each</span> <span style="color:grey">case</span>, the <span style="color:grey">module</span> <span style="color:grey">borders</span> <span style="color:grey">mark</span> where the <span style="color:grey">service</span> would <span style="color:grey">divide</span>.
