# Reading the three harder files

**The short answer.** `Settings.cs`, `Database.cs` and `Catalogue.cs` <span style="color:grey">each</span> lean on <span style="color:grey">one</span> <span style="color:grey">idea</span> that ASP.NET Core or Npgsql <span style="color:grey">supplies</span>. <span style="color:grey">Learn</span> the <span style="color:grey">idea</span> <span style="color:grey">first</span>, and <span style="color:grey">each</span> <span style="color:grey">file</span> <span style="color:grey">reads</span> as <span style="color:grey">plain</span> C#. `Settings.cs` <span style="color:grey">uses</span> the <span style="color:grey">options</span> <span style="color:grey">pattern</span>, `Database.cs` a ***connection pool***, and `Catalogue.cs` a <span style="color:grey">background</span> <span style="color:grey">service</span>. <span style="color:grey">Each</span> <span style="color:grey">section</span> <span style="color:grey">below</span> <span style="color:grey">names</span> the <span style="color:grey">idea</span>, <span style="color:grey">shows</span> where the <span style="color:grey">file</span> <span style="color:grey">uses</span> it, and <span style="color:grey">lists</span> what surprises a <span style="color:grey">reader</span> <span style="color:grey">new</span> to ASP.NET Core.

## Settings.cs: the options pattern

**The idea.** ASP.NET Core <span style="color:grey">reads</span> every <span style="color:grey">setting</span> into <span style="color:grey">one</span> tree of <span style="color:grey">keys</span>, such as `Tiles:CacheSeconds`, from `tessera.json` and the <span style="color:grey">environment</span>. The <span style="color:grey">options</span> <span style="color:grey">pattern</span> <span style="color:grey">copies</span> <span style="color:grey">one</span> <span style="color:grey">branch</span> of that tree into a C# <span style="color:grey">record</span>, <span style="color:grey">checks</span> it, and <span style="color:grey">hands</span> it to <span style="color:grey">any</span> <span style="color:grey">code</span> that <span style="color:grey">asks</span>.

| Part | What it does |
|---|---|
| `AddFile` | <span style="color:grey">Adds</span> `tessera.json`, then the <span style="color:grey">environment</span> <span style="color:grey">again</span>, so a variable <span style="color:grey">wins</span> over the <span style="color:grey">file</span> |
| `Section<T>` | <span style="color:grey">Binds</span> <span style="color:grey">one</span> <span style="color:grey">section</span> to its <span style="color:grey">record</span>, <span style="color:grey">refuses</span> a <span style="color:grey">key</span> the <span style="color:grey">record</span> <span style="color:grey">lacks</span>, and <span style="color:grey">checks</span> <span style="color:grey">each</span> `[Range]` |
| `ValidateOnStart` | <span style="color:grey">Runs</span> the <span style="color:grey">checks</span> when the <span style="color:grey">program</span> <span style="color:grey">starts</span>, <span style="color:grey">rather</span> than on <span style="color:grey">first</span> <span style="color:grey">use</span> |
| `Check` | <span style="color:grey">Runs</span> every <span style="color:grey">check</span> at <span style="color:grey">once</span>; a <span style="color:grey">failure</span> <span style="color:grey">throws</span> with every <span style="color:grey">problem</span> it <span style="color:grey">found</span> |
| `IOptions<T>` | How <span style="color:grey">other</span> <span style="color:grey">code</span> <span style="color:grey">asks</span> for a <span style="color:grey">record</span>, such as `GetRequiredService<IOptions<TileSettings>>().Value` |

What surprises a newcomer:

- **`services` is a table, not a set of running programs.** It is the dependency-injection <span style="color:grey">container</span>: a <span style="color:grey">table</span> of 'when code asks for X, give it this'. `Register` <span style="color:grey">fills</span> the <span style="color:grey">table</span>, and `Build` in `Service.cs` <span style="color:grey">freezes</span> it.
- **The records hold no code to read JSON.** The binder <span style="color:grey">fills</span> <span style="color:grey">each</span> `init` <span style="color:grey">property</span> by its <span style="color:grey">name</span>; `[Range]` and `Validate` <span style="color:grey">carry</span> the <span style="color:grey">rules</span>.
- **The database's URL is not here.** `DatabaseConnection`, in `Sql/Connection.cs`, is a <span style="color:grey">class</span> with setters: `DatabaseConnections.Register` <span style="color:grey">sets</span> its <span style="color:grey">two</span> <span style="color:grey">values</span> <span style="color:grey">after</span> .NET <span style="color:grey">creates</span> it, which a <span style="color:grey">record</span> with `init` <span style="color:grey">properties</span> would <span style="color:grey">refuse</span>. It <span style="color:grey">lives</span> in `Sql`, the ***module*** <span style="color:grey">through</span> which the <span style="color:grey">service</span> <span style="color:grey">reaches</span> the <span style="color:grey">database</span>.

## Database.cs: one pool, and every failure as a value

**The idea.** <span style="color:grey">Opening</span> a <span style="color:grey">connection</span> to PostgreSQL <span style="color:grey">takes</span> <span style="color:grey">time</span>, so Npgsql <span style="color:grey">keeps</span> a <span style="color:grey">few</span> <span style="color:grey">open</span> in a <span style="color:grey">pool</span>, an `NpgsqlDataSource`, and <span style="color:grey">lends</span> <span style="color:grey">one</span> to <span style="color:grey">each</span> <span style="color:grey">query</span>. When all are <span style="color:grey">busy</span>, a <span style="color:grey">query</span> <span style="color:grey">waits</span> in a <span style="color:grey">queue</span>, <span style="color:grey">first</span> <span style="color:grey">come</span>, <span style="color:grey">first</span> <span style="color:grey">served</span> (N-26).

| Part | What it does |
|---|---|
| `Open` | <span style="color:grey">Makes</span> the <span style="color:grey">pool</span> from the <span style="color:grey">connection</span> <span style="color:grey">string</span> and the `Database` <span style="color:grey">section</span>: its <span style="color:grey">size</span>, how <span style="color:grey">long</span> a <span style="color:grey">query</span> may <span style="color:grey">run</span>, how <span style="color:grey">long</span> a <span style="color:grey">request</span> may <span style="color:grey">wait</span> |
| `Run` | <span style="color:grey">Borrows</span> a <span style="color:grey">connection</span>, <span style="color:grey">runs</span> the <span style="color:grey">work</span>, <span style="color:grey">returns</span> the <span style="color:grey">connection</span>, and <span style="color:grey">turns</span> an `NpgsqlException` into a `DatabaseError` |
| `Rows` and `Single` | The <span style="color:grey">two</span> <span style="color:grey">ways</span> the <span style="color:grey">service</span> <span style="color:grey">queries</span>; Dapper <span style="color:grey">fills</span> a <span style="color:grey">record</span> from <span style="color:grey">each</span> <span style="color:grey">row</span> by <span style="color:grey">column</span> <span style="color:grey">name</span> |
| `Ping` | <span style="color:grey">Sends</span> `SELECT 1` and <span style="color:grey">waits</span> <span style="color:grey">one</span> <span style="color:grey">second</span> at <span style="color:grey">most</span>, for `/health` (N-25) |
| `DatabaseError` | PostgreSQL's five-character SQLSTATE <span style="color:grey">code</span>, and <span style="color:grey">three</span> <span style="color:grey">questions</span> <span style="color:grey">about</span> it: has the <span style="color:grey">table</span> <span style="color:grey">gone</span>, has a <span style="color:grey">column</span> <span style="color:grey">gone</span>, may <span style="color:grey">waiting</span> <span style="color:grey">cure</span> it |

What surprises a newcomer:

- **No method throws for a database failure.** <span style="color:grey">Each</span> <span style="color:grey">returns</span> a `Result`, which <span style="color:grey">holds</span> the <span style="color:grey">answer</span> or the <span style="color:grey">reason</span> (ADR 0004). <span style="color:grey">Read</span> `Result<T, DatabaseError>` as 'a `T`, or a `DatabaseError`'.
- **`await using` returns the connection.** When the <span style="color:grey">block</span> <span style="color:grey">ends</span>, <span style="color:grey">even</span> <span style="color:grey">through</span> an <span style="color:grey">error</span>, the <span style="color:grey">connection</span> <span style="color:grey">goes</span> <span style="color:grey">back</span> to the <span style="color:grey">pool</span>. No <span style="color:grey">code</span> <span style="color:grey">closes</span> <span style="color:grey">one</span> by <span style="color:grey">hand</span>.
- **`Ping` keeps two clocks.** A <span style="color:grey">cancel</span> <span style="color:grey">signal</span> <span style="color:grey">takes</span> it out of the <span style="color:grey">pool</span>'s <span style="color:grey">queue</span> <span style="color:grey">after</span> a <span style="color:grey">second</span>, and `WaitAsync` <span style="color:grey">stops</span> the <span style="color:grey">wait</span> <span style="color:grey">after</span> a <span style="color:grey">second</span> <span style="color:grey">even</span> when a <span style="color:grey">frozen</span> <span style="color:grey">database</span> <span style="color:grey">ignores</span> the <span style="color:grey">cancel</span>.

## Catalogue.cs: a list that refreshes in the background

**The idea.** A `BackgroundService` is a loop that ASP.NET Core <span style="color:grey">starts</span> with the <span style="color:grey">program</span> and <span style="color:grey">stops</span> with it. `LiveCatalogue` <span style="color:grey">uses</span> <span style="color:grey">one</span> to <span style="color:grey">reread</span> the <span style="color:grey">list</span> of ***layers*** every `Catalogue.RefreshSeconds`, so a <span style="color:grey">table</span> <span style="color:grey">granted</span> <span style="color:grey">later</span> <span style="color:grey">appears</span> <span style="color:grey">without</span> a <span style="color:grey">restart</span> (N-23).

| Part | What it does |
|---|---|
| `Queries.Layers` | <span style="color:grey">Asks</span> PostgreSQL's <span style="color:grey">own</span> <span style="color:grey">tables</span>, `pg_class` and `pg_attribute`, which <span style="color:grey">tables</span> and <span style="color:grey">views</span> the <span style="color:grey">reader</span> may <span style="color:grey">read</span>, and which <span style="color:grey">hold</span> a <span style="color:grey">typed</span> geometry <span style="color:grey">column</span> |
| `LayerCatalogue` | The <span style="color:grey">list</span> at <span style="color:grey">one</span> <span style="color:grey">moment</span>; it <span style="color:grey">never</span> <span style="color:grey">changes</span>, and a refresh <span style="color:grey">builds</span> a <span style="color:grey">new</span> <span style="color:grey">one</span> |
| `Refresh` | <span style="color:grey">Loads</span> a <span style="color:grey">list</span>; on <span style="color:grey">success</span> it <span style="color:grey">swaps</span> the <span style="color:grey">list</span> in <span style="color:grey">whole</span>, and on <span style="color:grey">failure</span> it <span style="color:grey">keeps</span> the <span style="color:grey">old</span> <span style="color:grey">one</span> and logs a <span style="color:grey">warning</span> |
| `ExecuteAsync` | The loop: refresh, <span style="color:grey">wait</span>, <span style="color:grey">repeat</span>; until the <span style="color:grey">first</span> <span style="color:grey">list</span> <span style="color:grey">loads</span>, it <span style="color:grey">waits</span> `retry` <span style="color:grey">rather</span> than `every` |

What surprises a newcomer:

- **Many requests read the list while the loop replaces it.** `Interlocked.Exchange` and `Volatile.Read` <span style="color:grey">make</span> the <span style="color:grey">swap</span> a <span style="color:grey">single</span> <span style="color:grey">step</span>, so a <span style="color:grey">request</span> <span style="color:grey">sees</span> the <span style="color:grey">old</span> <span style="color:grey">list</span> or the <span style="color:grey">new</span> <span style="color:grey">one</span>, <span style="color:grey">never</span> <span style="color:grey">half</span> of <span style="color:grey">each</span>.
- **The SQL lives elsewhere.** `Queries.Layers` <span style="color:grey">sits</span> in `Queries.cs`, <span style="color:grey">since</span> every SQL <span style="color:grey">text</span> <span style="color:grey">lives</span> in <span style="color:grey">one</span> <span style="color:grey">file</span> (S-01).
- **`Service.cs` registers `LiveCatalogue` twice.** <span style="color:grey">Once</span> as a <span style="color:grey">plain</span> <span style="color:grey">object</span>, so the ***tile*** <span style="color:grey">route</span> and `/health` can <span style="color:grey">read</span> it, and <span style="color:grey">once</span> as a <span style="color:grey">hosted</span> <span style="color:grey">service</span>, so ASP.NET Core <span style="color:grey">runs</span> its loop.
